## 0. 一次切分的运气问题

测试集只有 179 人，**换个 random_state 重新切，分数能差好几个百分点**——单次成绩有运气成分，信不过。

## 1. 五折交叉验证：轮流考试

把**训练集**切成 5 份（折，fold），轮流拿 1 份当考试卷、其余 4 份当教材，跑 5 次取平均：

```
第1轮: [考][学][学][学][学]  → 分数①
第2轮: [学][考][学][学][学]  → 分数②
第3轮: [学][学][考][学][学]  → 分数③
第4轮: [学][学][学][考][学]  → 分数④
第5轮: [学][学][学][学][考]  → 分数⑤
                             平均 ± 标准差 = 可信成绩
```

好处：**每份数据都被考过且只被考一次**，成绩不再依赖某一次切分的运气。

## 2. 代码只有一行

```python
from sklearn.model_selection import cross_val_score
scores = cross_val_score(model, X_train, y_train, cv=5)   # 返回 5 个分数的数组
print(scores.mean(), scores.std())
```

- `mean` = 可信的平均水平
- `std`（标准差）= **稳定性**：std 大 → 模型对数据敏感、成绩靠运气；std 小 → 稳

## 3. 铁律：测试集不参加 CV

CV 只在**训练集**上做（所以代码里传 `X_train, y_train`）。那 179 人的测试集是"期末考"，**全程不能碰，最后才碰一次**——否则它也变成了复习题。

## 4. 用 CV 做比较 = GridSearch 的手工版

换模型比一比（森林 vs 单树）、扫超参数（depth 1~10）都用 CV 的 mean±std 说话——这就是下周 GridSearchCV 自动化的手工版。
